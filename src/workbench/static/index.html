Browser not starting? Setup & troubleshooting

The demo startup command does not start the browser. For LinkedIn, set WORKBENCH_MODE=live in .env, then run this in the project folder:

docker compose --profile live up --build -d --wait

Click Check connection, then Open browser here. The first browser image download can take a few minutes. If the viewer still refuses to connect, check docker compose --profile live ps and your configured BROWSER_PORT. On a remote machine, forward both the app and browser ports.

If a saved browser session is unavailable, restart only the browser with docker compose --profile live restart browser, then reset its connection below. This preserves cookies and never retries invitations.

Google connection setup
Each installation needs its own Google OAuth web application client. Enable Google Sheets API, configure the consent screen with the drive.file scope, and add your Google account as a test user while testing.
Download the client JSON to secrets/google-oauth-client.json. Set GOOGLE_OAUTH_CLIENT_FILE=/run/secrets/google-oauth-client.json and GOOGLE_OAUTH_REDIRECT_URI=http://localhost:8080/api/connections/google/callback in .env. Register that exact callback in Google; use your actual app port. Recreate the app after editing settings.
For an existing workbook, the service-account method remains supported: share an empty workbook with the service account and configure GOOGLE_SHEET_ID and GOOGLE_APPLICATION_CREDENTIALS. OAuth currently creates its own workbook; an existing-file picker is not included.
